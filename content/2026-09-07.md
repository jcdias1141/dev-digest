    source: "https://code.claude.com/docs/en/changelog"
    body: |
      A sequência de versões 2.1.260 a 2.1.269 (3 a 11 de setembro)
      concentrou vários recursos de uso direto no dia a dia. O /diff abre um
      painel ao lado da conversa em modo tela cheia, mostrando as mudanças
      ainda não commitadas à medida que o Claude edita — dá para acompanhar
      o diff sem alternar para o terminal do git. O claude plugin eval roda
      a suíte de avaliação de um plugin contra o Claude Code e devolve
      resultado pontuado e reproduzível, em JSON e relatório HTML — útil
      para quem mantém plugin próprio e quer testar mudanças antes de
      publicar.

      O /skill-doctor lista quais skills carregadas na sessão não estão
      sendo usadas e quanto contexto cada uma consome, para podar o que está
      sobrando. E o /output-style [nome] permite listar e trocar o estilo de
      saída direto pelo prompt, inclusive em sessões via Remote Control ou
      headless na nuvem.

      ## Por que importa

      Nenhum desses recursos muda comportamento por padrão — são
      ferramentas de diagnóstico e conveniência para quem já sente o atrito
      específico que cada um resolve. Se você mantém um plugin ou foi
      acumulando skills ao longo do tempo, vale rodar plugin eval e
      /skill-doctor pelo menos uma vez para ver o que sobrou sem uso.

      Duas mudanças de configuração miram uso não interativo e em
      organização: managedMcpServers (v2.1.265, 8 de setembro) permite a uma

      central em vez de cada projeto declarar o próprio .mcp.json, e
      --permission-prompts none, na mesma versão, roda o Claude Code sem
      pedir aprovação interativa — pensado para CI e tarefas agendadas, onde
      qualquer coisa que pediria confirmação é negada automaticamente
      enquanto o modo estiver ativo. Já maxEffortLevel (v2.1.267, 9 de
      setembro) limita o nível de esforço de raciocínio em qualquer
      provedor (Bedrock, Vertex, Foundry), configurável no nível geral ou
      por modelo.

      ## Por que importa

      Se você automatiza tarefas do Claude Code fora de uma sessão
      interativa — CI, cron, rotina agendada — o --permission-prompts none é
      o flag que faltava para isso não travar esperando aprovação que
      ninguém vai dar. E quem já roda MCP em equipe ganha uma forma de
      distribuir servidor sem depender de cada pessoa configurar o próprio
      .mcp.json.

      trabalha sozinho, vale menos como substituto do fluxo atual e mais
      como algo a observar — a pergunta prática é quanto controle e revisão
      o coordenador deixa antes de abrir um PR.

  - title: "React 19.3 estabiliza View Transitions e Fragment Refs"
    category: "Frameworks"
    summary: >-
      O React 19.3, lançado em 9 de setembro, estabiliza dois recursos que
      estavam experimentais: o componente ViewTransition, para animações
      declarativas de transição entre telas ou elementos, e Fragment Refs,
      uma referência que aponta para um grupo de elementos sem precisar de
      um elemento wrapper único no DOM. A versão também separa o
      processamento de transições do restante do ciclo de render, em vez de
      misturar os dois num só passo.
    source: "https://react.dev/blog/2026/09/09/react-19-3"
    body: |
      A 19.3 tira do experimental dois recursos que vinham sendo testados
      desde versões anteriores. O ViewTransition permite declarar animações
      de transição — entre rotas, ao mostrar ou esconder um elemento, ao
      reordenar uma lista — sem sair do modelo declarativo do React, usando
      a View Transitions API do navegador por baixo. Fragment Refs resolve
      um caso comum de frustração: hoje, para ter uma ref sobre um grupo de
      elementos, é preciso envolver tudo numa div ou outro wrapper só para
      isso; a nova API dá uma ref sobre o próprio Fragment, sem elemento
      extra no DOM.

      A versão também separa o processamento de transições do resto do
      ciclo de render — antes, tudo ficava entrelaçado num único passo de
      render, o que podia causar travamento perceptível quando uma
      transição concorria com atualização de estado normal. Vieram junto
      suporte a Trusted Types em react-dom/server e uma função browser()
      para renderização exclusiva no navegador.

      ## Por que importa

      Para quem já usa Tailwind e CSS/SASS para animação manual, o
      ViewTransition é a primeira forma nativa do React de declarar
      transição sem sair do componente — vale testar em vez de manter uma
      solução própria com classes de transição e useEffect. Fragment Refs
      remove um wrapper div que provavelmente já existe em algum componente
      só para conseguir uma ref.
