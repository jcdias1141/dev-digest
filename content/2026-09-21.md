    category: "Claude Code"
    summary: >-
      A v2.1.277 (18 de setembro) fez o Claude Code passar a ler o arquivo
      AGENTS.md quando o projeto não tem CLAUDE.md, sem precisar de import ou
      atalho manual. O CLAUDE.md continua valendo quando os dois existem, e dá
      para trocar qual arquivo é lido em Project instructions, dentro do
      config. O suporte ainda não chegou ao Bedrock, Vertex nem Foundry.
    source: "https://code.claude.com/docs/en/changelog"
    body: |
      Até a v2.1.277 (18 de setembro), um projeto sem CLAUDE.md simplesmente
      não tinha instrução de projeto nenhuma para o Claude Code — mesmo que já
      existisse um AGENTS.md escrito para outra ferramenta. Agora, na ausência
      de CLAUDE.md, o Claude Code lê o AGENTS.md do projeto diretamente, sem
      precisar de um arquivo-ponte importando um no outro. Quando os dois
      arquivos existem, CLAUDE.md continua tendo prioridade; qual dos dois é
      lido pode ser trocado manualmente em "Project instructions", dentro do
      `/config`.

      AGENTS.md é um formato aberto, mantido pela Agentic AI Foundation sob a
      Linux Foundation, e já era lido por mais de trinta ferramentas — Cursor,
      GitHub Copilot, OpenAI Codex e Google Jules entre elas. Até aqui, quem
      usava Claude Code ao lado de outro agente no mesmo repositório
      precisava manter os dois arquivos sincronizados à mão, ou usar um
      import de um dentro do outro. A ressalva: o suporte ainda não chegou ao
      Bedrock, Vertex nem Foundry, então quem roda o Claude Code por essas
      plataformas continua precisando de CLAUDE.md por enquanto.

      ## Por que importa

      Quem já mantinha AGENTS.md para outro agente (Cursor ou Copilot, por
      exemplo) ganha compatibilidade com o Claude Code de graça, sem duplicar
      arquivo. Se você tem os dois arquivos hoje só por precaução, dá para
      simplificar: com CLAUDE.md ausente, o AGENTS.md já basta, contanto que
      não esteja rodando via Bedrock, Vertex ou Foundry.
  - title: "Correção de segurança: rm perigoso escapava do bypass mode via subshell"
    category: "Claude Code"
    summary: >-
      A v2.1.273 (15 de setembro) corrigiu o verificador de permissão do Bash
      no modo bypass, que deixava passar um comando rm perigoso quando ele
      vinha dentro de um subshell. Antes da correção, um comando composto
      podia escapar da checagem de segurança mesmo com o bypass mode ativo,
      que existe justamente para reduzir prompts de confirmação, não para
      abrir brecha de comando destrutivo.
    source: "https://code.claude.com/docs/en/changelog"
    body: |
      O bypass mode do Claude Code existe para quem quer rodar sessões sem
      ficar confirmando cada comando de permissão — mas ele ainda deveria
      barrar um `rm` claramente perigoso (por exemplo, um `rm -rf` sobre
      caminho sensível). A v2.1.273 (15 de setembro) corrigiu um caso em que
      esse tipo de comando escapava da checagem quando vinha embrulhado num
      subshell, por exemplo `$(...)` ou `(...)` dentro da linha de comando —
      o verificador de permissão olhava a estrutura externa do comando e não
      enxergava o `rm` escondido dentro do subshell.

      Não há indicação de exploração ativa; é uma correção preventiva de um
      bug real de checagem, não resposta a um incidente. Ainda assim, é o
      tipo de falha que só aparece quando alguém (ou o próprio Claude, gerando
      um comando composto) monta um comando de um jeito que o parser de
      permissão não previa.

      ## Por que importa

      Se você usa bypass mode com regularidade — em CI, em rotina agendada ou
      numa sessão de terminal onde já confia no que está rodando — vale
      atualizar para a v2.1.273 ou mais recente. O bypass mode reduz atrito de
      permissão, mas não deveria significar zero rede de segurança contra
      comando destrutivo; essa correção fecha uma das formas conhecidas de
      driblar essa rede.
  - title: "Auto mode passa a rodar o classificador no servidor sem cobrar overhead"
    category: "Claude Code"
    summary: >-
      A v2.1.278 (19 de setembro) mudou o auto mode para usuários de Claude
      API, Enterprise, e em Bedrock, Vertex, Foundry e gateways: por padrão,
      o classificador que decide a ação automática passa a rodar no lado do
      servidor da Anthropic, sem cobrar o custo de token do próprio
      classificador. Quem quiser manter o comportamento anterior pode reverter
      com uma variável de ambiente.
    source: "https://code.claude.com/docs/en/changelog"
    body: |
      O auto mode do Claude Code usa um classificador para decidir
      automaticamente que ação tomar em determinados pontos da sessão. Até a
      v2.1.278 (19 de setembro), rodar esse classificador consumia tokens
      como qualquer outra chamada de modelo, cobrados normalmente. A partir
      dessa versão, para usuários de Claude API e Enterprise, e em Bedrock,
      Vertex, Foundry e gateways, o classificador passa a rodar por padrão no
      lado do servidor da Anthropic — sem gerar cobrança de overhead por essa
      classificação. Em Bedrock, Vertex, Foundry e gateways, dá para manter o
      comportamento antigo (classificador rodando pelo lado do cliente, com
      custo normal) definindo `CLAUDE_CODE_AUTO_MODE_SERVER=0`; se o servidor
      não estiver disponível e a sessão cair para o modo cobrado, o Claude
      Code avisa. O `/status` ganhou uma linha "Auto mode server" mostrando se
      o classificador da sessão atual está rodando do lado do servidor.

      ## Por que importa

      É redução de custo direta para quem já usa auto mode com frequência,
      sem exigir nenhuma configuração — o padrão novo já economiza sozinho.
      Vale conferir a linha "Auto mode server" no `/status` para confirmar
      que sua sessão está de fato usando o classificador do lado do servidor,
      principalmente se você roda via Bedrock, Vertex, Foundry ou gateway
      próprio, onde a opção antiga (cobrada) ainda pode estar ativa por
      configuração local.

    source: "https://code.claude.com/docs/en/changelog"
    body: |
      A v2.1.271 (14 de setembro) trouxe para o menu Customize da extensão do
      VS Code duas entradas novas: Memory, que mostra os toggles de
      auto-memória, as memórias salvas e as pastas de memória, e
      Instructions, que edita os arquivos CLAUDE.md direto pela interface. Três
      dias depois, a v2.1.274 (17 de setembro) completou o diálogo de Memory
      com a capacidade de ver, editar e apagar uma memória salva sem sair
      dali — antes só dava para visualizar.

      Na mesma leva, a v2.1.275 (17 de setembro) adicionou a tecla de "enviar
      agora": ctrl+enter, ou ctrl+x ctrl+s, interrompe o turno em andamento e
      manda de uma vez todas as mensagens que você tinha deixado na fila
      enquanto o Claude ainda respondia. As mensagens enviadas e as que ainda
      estão na fila aparecem em cinza até o modelo efetivamente recebê-las.

      ## Por que importa

      Editar memória salva sem abrir o arquivo markdown à mão é conveniência
      pura — reduz o atrito de manter o CLAUDE.md e as memórias automáticas
      arrumados ao longo do tempo. A tecla de enviar agora resolve um atrito
      comum de quem enfileira várias instruções seguidas achando que o Claude
      vai processá-las em sequência: agora dá para forçar o envio imediato em
      vez de esperar o turno atual terminar sozinho.

    body: |
      O release semanal do GitHub Copilot cobrindo 8 a 14 de setembro,
      publicado em 18 de setembro, trouxe três mudanças de uso direto. A
      seleção automática de modelo ganhou três níveis — eficiência,
      equilíbrio e inteligência — que priorizam de forma diferente custo,

      Os três níveis de seleção automática são úteis para quem deixa o
      Copilot escolher o modelo sozinho na maior parte do tempo e quer expor
      essa escolha em vez de aceitar um meio-termo fixo — dá para inclinar
      para custo baixo numa tarefa repetitiva e para qualidade numa tarefa
      mais delicada, sem trocar de modelo manualmente a cada vez. Já a
      integração com Sentry vale mais para quem já usa o app do Copilot como
      hub de tarefas do dia a dia, menos para quem trabalha só pelo CLI ou
      pela extensão do editor.
  - title: "Grok Build ganha memória persistente entre sessões"
    category: "Outras ferramentas"
    summary: >-
      A xAI tornou geral, em 16 de setembro (v1.0.34), a memória entre
      sessões do Grok Build, seu agente de código de terminal: convenções,
      decisões e fatos do projeto passam a ser anotados em arquivos markdown
      em segundo plano e lidos de volta em sessões futuras. Os comandos
      /memory e /dream dão controle manual sobre o que fica salvo.
    source: "https://x.ai/news/grok-build-memory"
    body: |
      Diferente do CLAUDE.md do Claude Code — um arquivo que você escreve à
      mão — a memória do Grok Build é gerada pelo próprio agente enquanto
      trabalha: ele anota convenções, decisões e fatos do projeto que surgem
      durante uma sessão em arquivos markdown organizados por tópico, e lê
      essas notas de volta antes de mexer em código relacionado numa sessão
      seguinte. O sistema filtra automaticamente estado temporário de tarefa,
      inferência ainda não madura, informação confidencial e conteúdo que já
      está documentado no próprio código ou na documentação do projeto.

      Dois comandos dão controle manual sobre esse processo: /memory abre um
      navegador somente leitura de todos os arquivos de memória, agrupados
      por escopo, com prévia do arquivo selecionado; /dream incorpora
      observações novas aos arquivos de tópico relevantes sob demanda — o
      mesmo processo também roda periodicamente em segundo plano, sozinho. A
      captura de nota começa depois do primeiro turno completo de uma sessão,
      e é preciso abrir uma sessão nova (/new ou um grok novo) para o
      contexto salvo valer.

      ## Por que importa

      É uma aposta diferente da do Claude Code: em vez de um arquivo de
      instrução que você escreve e mantém, o Grok Build tenta manter memória
      de projeto sozinho, sem esforço manual — trocando previsibilidade (você
      sabe exatamente o que está no CLAUDE.md porque escreveu) por
      conveniência (a memória se acumula sem que você precise lembrar de
      atualizar nada). Vale só para quem já usa o Grok Build; não há
      integração anunciada com o fluxo do Claude Code.
