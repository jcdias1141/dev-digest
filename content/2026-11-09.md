    category: "Claude Code"

      A v2.1.318 (4 de novembro) mudou o comportamento da extensão do VS
      Code: ela deixa de se instalar ou atualizar sozinha quando a sessão do
      Claude Code é aberta a partir do terminal integrado do próprio IDE.
      Para instalar ou atualizar a extensão agora é preciso rodar /ide a
      partir de um terminal externo, ou usar a aba de extensões do editor.
    source: "https://code.claude.com/docs/en/changelog"
    body: |
      Até a v2.1.317, abrir uma sessão do Claude Code dentro do terminal
      integrado do VS Code podia disparar a instalação ou atualização
      automática da extensão da IDE, mesmo sem pedido explícito. A v2.1.318,
      de 4 de novembro, muda esse comportamento: rodar o Claude Code nesse
      contexto não toca mais na extensão.

      Para instalar ou atualizar a extensão continua dando pra fazer de dois
      jeitos: rodando /ide a partir de um terminal externo ao VS Code, ou
      pela própria aba de extensões do editor, como qualquer outra extensão.

      ## Por que importa

      É uma mudança discreta, mas evita um efeito colateral que surpreendia
      quem só queria abrir uma sessão de terminal dentro do VS Code sem
      necessariamente querer atualizar a extensão instalada naquele momento
      — por exemplo, no meio de uma tarefa, onde uma versão nova da extensão
      poderia mudar algo em andamento. Quem depende da auto-atualização para
      manter a extensão sempre na versão mais recente deve passar a rodar
      /ide manualmente de vez em quando, ou atualizar pela aba de extensões
      do VS Code.
  - title: "Tarefa MCP longa passa a rodar em segundo plano automaticamente no terminal"
    category: "Claude Code"
    summary: >-
      A v2.1.319 (6 de novembro) passou a mover automaticamente para segundo
      plano, no terminal, qualquer chamada de ferramenta que um servidor MCP
      execute como task — a sessão principal não fica mais travada
      esperando, e recebe o resultado quando a tarefa termina. Dá para
      voltar ao comportamento anterior com
      CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND.
    source: "https://code.claude.com/docs/en/changelog"
    body: |
      Antes da v2.1.319, de 6 de novembro, uma chamada de ferramenta de um
      servidor MCP que levasse tempo para terminar — um scraping longo, um
      build externo, uma consulta pesada — travava a sessão de terminal até
      a resposta voltar, do mesmo jeito que uma chamada de ferramenta
      comum. A v2.1.319 passou a tratar esse caso de forma diferente quando
      o servidor MCP sinaliza a chamada como uma task: o Claude Code move a
      execução para segundo plano imediatamente e só avisa o resultado
      quando ela termina, sem bloquear o resto da sessão nesse meio tempo.

      O comportamento antigo (bloquear até a task MCP terminar) volta com a
      variável de ambiente CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND.

      ## Por que importa

      Quem usa servidor MCP com chamada de longa duração — por exemplo,
      algo que dispara um processo externo ou faz scraping de várias
      páginas — deixa de precisar estruturar isso manualmente como
      subagente em segundo plano só para não travar a sessão principal. É o
      mesmo ganho que o fork subagent trouxe para o Agent tool, agora
      aplicado nativamente a quem constrói ferramenta MCP própria.
  - title: "Duas mudanças da v2.1.319 facilitam sessão não interativa: negar permissão em vez de esperar, e /loop que termina sozinho"
    category: "Claude Code"
    summary: >-
      A v2.1.319 (6 de novembro) trouxe duas mudanças separadas voltadas
      para sessão não interativa. permissions.denyInsteadOfPrompting faz
      uma chamada que esperaria por um prompt de permissão ser negada
      direto, em vez de travar a sessão, em terminal, subagente e teammate.
      E o /loop autopaced (sem intervalo fixo) passou a terminar quando um
      turno acaba, em vez de se reagendar sozinho — reversível com
      CLAUDE_CODE_LOOP_KEEPALIVE=1.
    source: "https://code.claude.com/docs/en/changelog"
    body: |
      A v2.1.319, de 6 de novembro, trouxe duas mudanças de comportamento
      pensadas para quem roda o Claude Code sem alguém na frente da tela
      esperando responder prompt.

      A primeira é a configuração permissions.denyInsteadOfPrompting: antes,
      uma chamada de ferramenta que exigisse confirmação de permissão numa
      sessão sem ninguém para responder simplesmente ficava esperando — sem
      essa config, a sessão trava. Com ela ligada, a chamada é negada na
      hora e o turno continua, em sessão de terminal, subagente e teammate.

      A segunda é uma mudança no /loop em modo autopaced (sem intervalo
      fixo, deixando o próprio Claude decidir quando voltar): antes, ao
      terminar um turno, o loop se reagendava sozinho com um wakeup de
      fallback. Agora ele termina quando o turno acaba, sem reagendar — quem
      quer manter o comportamento antigo liga CLAUDE_CODE_LOOP_KEEPALIVE=1.

      ## Por que importa

      As duas mudanças miram o mesmo problema: sessão sem humano por perto
      não pode depender de alguém clicar em "permitir". denyInsteadOfPrompting
      evita que uma automação (como esta própria rotina semanal) trave para
      sempre esperando um prompt que nunca vai ser respondido. Já a mudança
      no /loop afeta quem usa o modo autopaced esperando que ele fique se
      reagendando indefinidamente — depois da v2.1.319, isso para de
      acontecer por padrão, e vale revisar qualquer loop próprio que contava
      com o comportamento antigo.

    source: "https://github.blog/changelog/2026-11-06-github-copilot-in-slack-and-teams-is-generally-available"
    body: |
      O @GitHub permite mencionar o bot direto numa conversa do Slack ou do
      Microsoft Teams para pedir que ele investigue um bug, crie uma issue,
      implemente uma mudança de código ou abra um pull request — sem
      precisar abrir o GitHub ou um editor. Em 6 de novembro, o recurso saiu
      do preview e ficou geralmente disponível nas duas plataformas.

      A atualização trouxe o Canvas para o Teams: um painel ao lado da
      conversa para revisar o plano da mudança, o diff proposto e um
      preview, em vez de rolar mensagem de chat para acompanhar. O
      onboarding também ficou mais rápido, detectando automaticamente qual
      repositório a mensagem se refere, e um bug de mensagem de
      acompanhamento sem resposta foi corrigido. Issue e pull request
      criados por essa via agora citam que vieram de uma conversa no Slack
      ou Teams.

      ## Por que importa

      É o GitHub formalizando "chat de equipe como entrada de código" como
      caminho de produção, não mais preview — categoria que o Claude Code
      não cobre nativamente hoje, sem integração oficial de Slack ou Teams.
      Para quem trabalha sozinho, o impacto direto é baixo, mas é um padrão
      para observar: se o fluxo "peça num chat, receba um PR" comprovar
      valor em equipe, é provável que apareça também como opção na extensão
      do Claude Code ou via MCP mais adiante.

    body: |
      O Build Live Apps, lançado pelo Cursor em 5 de novembro, empacota o
      caminho inteiro de "pedido em linguagem natural" até "app publicado"
      num fluxo só: um cloud agent monta a aplicação, provisiona um banco
      Postgres quando a aplicação precisa de um, configura autenticação via
      SSO do próprio Cursor, e publica num domínio escolhido. Antes de ir ao
      ar, o fluxo roda uma checagem determinística e agêntica contra segredo
      exposto no código, e a publicação exige aprovação explícita — não vai
      ao ar sozinho sem confirmação.

      O recurso funciona tanto com repositório hospedado no GitHub quanto no
      Origin, a própria plataforma de hospedagem de código na nuvem do
      Cursor (lançada em agosto, coberta aqui quando ganhou marketplace de
      integrações em outubro). Está disponível em qualquer plano pago do
      Cursor que tenha cloud agents habilitados.

      ## Por que importa

      É o Cursor competindo diretamente como destino de deploy — não só
      como editor — contra serviço como Vercel ou Railway, que o leitor já
      usa manualmente hoje. Vale observar se o recurso sai do estágio de
      demonstração e passa a ser usado em projeto real antes de considerar
      substituir um fluxo de deploy já estabelecido; a checagem de segredo
      exposto antes de publicar é bom sinal de segurança básica, mas não
      dispensa revisão própria do que está sendo publicado.

    body: |

      é outra coisa: uma chamada de voz em tempo real onde o próprio agente
      responde falando, narra o progresso enquanto trabalha e resume o que

      É diferenciação de experiência multimodal e mobile, não mudança de
      fluxo de trabalho de terminal — baixo impacto prático para quem
      desenvolve via Claude Code no terminal e VS Code. Vale como sinal de
      para onde o Cursor está investindo (voz, mobile) enquanto o Claude
      Code segue priorizando controle fino de subagente, esforço e
      automação de terminal.

      do Claude Code. Vale acompanhar se a Cognition ou terceiros publicam
      número de benchmark consistente antes de usar o SWE-2 Flash como
      referência de custo-benefício; por ora, os números em circulação são
